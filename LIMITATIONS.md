# Limitations and missing evidence

- One task instance per category/configuration does not estimate overall reliability, production success rates or model superiority. Do not pool browser, desktop, smoke and later UI-TARS cohorts.
- Original GitHub prompts and detailed runtime variants differ. Browser references are historical snapshots, not current website truth. Provider models, browsers, profiles and managed hardware differ.
- The form fixture and four added desktop specifications were reconstructed before their actual runs under authorization. Their frozen originals are recoverable; unknown earlier specifications are not. No reconstructed example was substituted for an actual agent output.
- Form message punctuation supports two reasonable interpretations. Strict and sensitivity scores remain distinct. TinyFish’s other three visible omissions and two unverified fields are independent of that ambiguity.
- Relative GitHub dates can satisfy a permitted fallback while losing strict exact-calendar-date points. Correct issue selection is distinct from exact date precision.
- A correct output file does not prove reopening/verification. Claude CSV and its first recovery attempt preserve that distinction. File organization was interrupted by infrastructure, not a clean capability-only failure.
- Claude’s CSV sleep/clock discrepancy and OpenAI’s early missing click modifiers confound timing/actions. Local host contention was not measured. Native actions, hosted steps, waits and saved screenshots are different units.
- Sai browser runs, separate frontend desktop activity and the direct-control API blocker are distinct. No independently scoreable frontend desktop trace/artifact was recovered from the audited folders. API HTTP 403 prevented desktop submission; do not assign zero task accuracy or infer that all product routes are unavailable.
- UI-TARS’s original follow-up, earlier setup blocks, four unsubmitted tasks and five later different failures retain separate statuses. Navigation success is not full benchmark completion. The suspected retry/status interaction was not repaired or tested during publication.
- TinyFish’s model revision and provider-internal retries are unavailable. Some providers expose aliases rather than immutable model revisions. Some still counts and task-attributable costs are unavailable; a final answer cannot fill those gaps.
- A five-transaction TinyFish wallet export was not recovered. Sai’s unallocated cent and alternative usage figure cannot be reconciled as invoices. UI-TARS’s later-suite hosting attribution and input/output token split are unavailable. Account-period totals are not per-task bills.
- No genuine video for the five in-scope configurations was recovered in the prior media audit. Reviewed stills and native traces are included; no synthetic screenshots or reconstructed videos were created. Other stills remain private and are not claimed missing solely because excluded from publication.
- Historical source scripts require manual environment configuration. The original custom local desktop base image is not supplied as a public registry artifact. Hosted account access, deployed fixture availability and current model access can prevent full execution reproduction. Offline grading is more portable; one-command agent reproduction is not claimed.
- Public evidence is sanitized: credentials, capability URLs, account metadata, browser profiles and sensitive local paths are omitted. Historical references to private files do not mean those binaries are public. Public GitHub target names and genuine issue titles remain task data; outside-scope evaluated-agent evidence is excluded.
- Source repositories and prior commits remain private and unchanged. This scoped repository starts a separate publication history so excluded evaluations are not carried invisibly in old commits.

## Form follow-up limitation

[Three TinyFish reruns](browser-benchmarks/reruns/tinyfish-form-2026-10-22/README.md) improved the visible result to eight correct controls but never captured the newsletter. Serialized HTML did not retain live form properties. The message has an already disclosed alternative reading. These limits prevent a verified full pass without proving that every unverified state was wrong. Three new attempts and one historical Claude reference do not support a general reliability ranking; dates, capture options, browsers and timer boundaries differ.

## Clarified form configuration limitations

[Clarified results](browser-benchmarks/reruns/clarified-form-2026-10-22/README.md) contain a budget-cancelled TinyFish run, persistent missing TinyFish checkbox state, Claude post-run capture timeouts with usable prior screenshots, an unresolved cancelled-run charge, nonrandom provider order and different native/hosted timer boundaries. The changed prompt also adds verification instructions, so it does not isolate the message boundary as a causal factor. Nine confirmed TinyFish fields do not establish a wrong checkbox or a full pass. No general agent ranking follows from this sample.
