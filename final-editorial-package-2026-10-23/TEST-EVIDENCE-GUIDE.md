This is the editorial route through existing evidence, not a new benchmark protocol or a collection of replacement reports. The final article is [FINAL-ARTICLE.md](FINAL-ARTICLE.md); all eight selected figures and their captions/provenance are in [SELECTED-VISUALS](SELECTED-VISUALS/CAPTIONS.md). ## 1. Original GitHub browser task

**Purpose:** test whether the agent could navigate GitHub's website, filter open bug issues, sort by latest update and return five issue numbers, titles, URLs and update dates. The four fields per issue made 20 checks; correct membership/order also mattered. No login, repository edits or GitHub API use were allowed.

**Prompts:** agent-specific orchestration prompts and detailed native runtime variants survive. They were not perfectly identical and must not be retrospectively standardized: [runtime variants](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/tasks/original-github-attempt-variants.md). OpenAI explicitly allowed a disclosed relative-date fallback. Original Claude attempts used 300 seconds; other original deadlines/timer boundaries differed.

**Starting conditions/configurations:** Claude native Messages computer toolset in Firefox/Linux; OpenAI native Responses computer tool with a screenshot-driven Chromium executor; Sai pooled Windows cloud computer with routed model service; UI-TARS patched macOS development application and remote UI-TARS-1.5-7B for its later matching follow-up. Fresh-state support differed; a fresh conversation did not necessarily create a fresh pooled machine. Model aliases and tool identifiers: [environment/methodology](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/METHODOLOGY.md).

**Verified outcomes:** Claude 20/20 on its third attempt, after an output-token stop and local budget stop; OpenAI 15/20 with correct issue selection/order but relative dates; Sai no final answer by deadline; UI-TARS follow-up no final answer after seven actions and a timeout. UI-TARS's launch/token/permission blockers preceded that actual follow-up. These are not four clean first-attempt trials. Historical issue references support the old grades, not today's changing issue list.

**Inspect:** [per-attempt browser CSV](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/results/benchmark-results.csv); [original GitHub evidence](https://github.com/Andeubenye/computer-use-agent-benchmarks/tree/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/evidence/original-github/); [actual UI-TARS follow-up](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/evidence/ui-tars-original/results.json). Failed Claude attempts and their costs remain in the same historical cohort records.

## 4. Native desktop batch

**Why:** browser interaction alone does not show that an agent can operate spreadsheets, files, documents and cross-application workflows.

**Setup:** isolated Linux/Xvfb 1024×768, Openbox and LibreOffice 7.4.7.2. Both used native model computer tools; containers had no task-time network, host mounts or credentials. Claude used Messages/computer_toolset_20260801 and the recorded claude-sonnet-5-5 alias; OpenAI used Responses/computer and gpt-6.1-sol. Expected answers stayed outside the desktops. The CSV reused original input/prompt/rubric; the other four fixtures were reconstructed under authorization, then frozen, not claimed to recover unknown older specifications.

## 7. Engineering ownership audit

**Purpose:** identify what the actual integrations required, without running an agent or estimating invented labor hours.

**Method:** inspect the private originals and matched published execution snapshots, count disjoint effective source slices, classify provider/custom/reused/shared/test-only components, and reconstruct observable setup history. Physical lines include blanks/comments; differing code styles, instrumentation and reused code prevent treating the ratio as development time.

**Finding:** TinyFish 111 physical lines across 3 provider-specific units; Claude 1,044 across 8. TinyFish managed the browser host, actions and screenshot/model feedback loop. Our Claude stack owned a VM/container, Firefox, native executor, image forwarding and model loop. Both retained authentication bootstrap, policy, credentials, monitoring, costs and independent verification. Shared portal/test plumbing is not a differential vendor cost. Setup/maintenance hours and full ownership costs are UNKNOWN.

The actual architecture image and two short source excerpts are reproduced in the article, with exact original locations in RESULTS-AND-SOURCES. The diagram predates the persistent-profile add-on. Anthropic browser-specific/managed options were researched, not benchmarked; the audit doesn't describe every possible Claude application. [engineering audit](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/authenticated-workflows/supplier-portal-2026-10-22/ENGINEERING-EFFORT-AUDIT.md); [reproducible code inventory](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/authenticated-workflows/supplier-portal-2026-10-22/engineering-audit/code-inventory.json); [primary documentation research](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/authenticated-workflows/supplier-portal-2026-10-22/engineering-audit/research-sources.json).

## 8. Final session-durability experiment without Vault

**Purpose/task:** one [identical read-only prompt](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/session-durability/supplier-portal-2026-10-22/task-prompt.txt) required each agent to open the same dashboard and report whether already authenticated, with heading/account/supplier ID or a sign-in heading. It forbade login, credentials, edits, forms, direct website APIs and scripts. Authentication restoration and accurate diagnosis are separate measurements.

**Configurations:** fresh TinyFish login saved to a dedicated Profile, local setup clients/broker stopped, new controller and Web Agent run without portal password/cookies; original Claude fresh login then full container removal/recreation with no mounts; separate Claude configuration with a dedicated Docker volume at /home/agent/profile, login, removal and fresh container using that volume. Original implementation unchanged. Each diagnostic retained the 600-second limit without cost watchdogs.

**Results:** TinyFish restored the fresh setup session (36.94 seconds/$0.048 recorded); original Claude lost client login state (22.03 seconds/$0.058582 estimate) while the server session remained valid; persistent Claude restored it (20.98 seconds/$0.058560 estimate). All three diagnoses were correct. The extra lifecycle helper was 24 physical lines, including permissions/mount/cleanup. Same named volume and different container IDs establish the local boundary; matching server session aliases establish restored authenticated access without new login. [durability results](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/session-durability/supplier-portal-2026-10-22/results.json); [TinyFish server proof](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/session-durability/supplier-portal-2026-10-22/runs/tinyfish/server-verification.json); [Claude disposable proof](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/session-durability/supplier-portal-2026-10-22/runs/claude-existing/server-verification.json); [Claude persistent proof](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/session-durability/supplier-portal-2026-10-22/runs/claude-persistent/server-verification.json); [separate persistence helper](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/session-durability/supplier-portal-2026-10-22/harness/executed-source/persistent_runtime.py).

**Caveats:** one observation per configuration, different host/startup/polling visibility; no normalized speed/reliability inference. Both local shutdowns used Docker stop after quit didn't finish. A controller interruption and a pre-paid persistent setup failure/targeted repair are preserved. “Session expired” on the disposable browser was a generic page message, not evidence that the server session expired. Vault, expired-login reauthentication, MFA, disk/VM loss, production reliability and long-term maintenance savings were NOT TESTED. New API usage value totaled $0.165142, excluding unpriced infrastructure/labor. Original portal configuration was restored, new test sessions revoked and runtime stopped after collection. [durability methods and interruptions](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/session-durability/supplier-portal-2026-10-22/METHODOLOGY.md); [durability costs](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/session-durability/supplier-portal-2026-10-22/COSTS.md); [142 offline checks](https://github.com/Andeubenye/computer-use-agent-benchmarks/blob/3649bd37f4dcb6e9eb9823238deb116cdcc49fb9/browser-benchmarks/session-durability/supplier-portal-2026-10-22/verification.json).

## Editorial boundary

This package contains no new experiments, raw credential material, cookies, browser-profile storage, live setup/control URLs or synthetic passwords. Visible account labels, supplier IDs and confirmation receipts are synthetic task data, not login capability. The full evidence stays in place; publication packages superseded by this submission are not included. Conclusions are observations about these tested configurations, not universal rankings.
