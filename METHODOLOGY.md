# How I evaluated the agents

## Why browser work came first

I began with public website tasks because they gave browser agents and broader computer-use systems a shared, observable workflow. A website task still does not establish desktop capability. The later local-file tests used actual spreadsheet/document applications. TinyFish remains in the browser section because no desktop application test was submitted to it.

The original experiment covered six agents. This public edition scopes the saved evidence to five; it does not rewrite who participated or imply TinyFish was tested separately. The original four-task cohort had 20 runs. The scoped table retains 16 of those existing runs across TinyFish, Claude, OpenAI and Sai. UI-TARS’s matching four tasks were unsubmitted; its original-task follow-up and later five-different-prompt suite remain separate.

## What the harness could do

Before submission it staged original fixtures and opened the starting application. During a run it executed model-requested computer actions and captured observations. After stopping it collected files and read-only final state for independent grading. It could manage deadlines, costs and cleanup. It could not decide task edits, fill fields, calculate an answer for the model, finish a stalled dialog, supply grader references or replace an evaluated agent with Codex. Calc formulas entered by the model through the GUI were allowed for the sales task. Programmatic task editing, macros and shell completion were prohibited.

OpenAI’s browser driver used Playwright to execute the model’s structured actions; it did not solve the browser task. OpenAI’s desktop runs used the native Responses computer tool with ordered computer_call actions and paired screenshot outputs. Claude used native Messages computer toolsets. Managed providers exposed different browser/desktop capabilities; this was not uniformly a screenshot-only model comparison.

## Prompts, fixtures and scoring

Exact recovered original prompt files, hashes and runtime variants are linked from [task sheets](browser-benchmarks/README.md). Original GitHub instructions differed by agent and attempt. Do not collapse detailed native configurations into one short orchestration request. The four additional browser prompts were frozen shared strings. The form fixture was explicitly reconstructed before those runs because the older full specification was unavailable. Its recovered HTML is included; no replacement fixture was generated during publication.

The desktop CSV prompt, original input and five-point rubric are unchanged. The other four desktop tasks were reconstructed under explicit authorization, frozen and actually run identically for both models. They are not claimed to recover unknown earlier fixtures. [Desktop task sheets](desktop-benchmarks/tasks/README.md) quote every prompt and each one-point requirement. Expected answers were never staged in agent desktops.

Browser grading compares saved website observations, issue membership/order, dates, facts, final controls and required paths. Desktop grading compares exact parsed CSV values, original-file hashes, DOCX text/styles/tables, sales arithmetic and screenshot/action evidence of reopening. A saved correct file and a completed workflow are different findings. A final model message saying done is not proof. Historical GitHub references support historical grades, not today’s changing issue order. No GitHub API was used to perform or verify the website benchmark.

## Deadlines, repairs and spending

Additional browser and desktop attempts used a maximum 600 seconds. Original Claude GitHub trials retain their recorded 300-second harness limits. Some recorded submission-to-stop intervals include abort acknowledgement beyond the deadline. Setup, provider execution, queue time, client polling and cleanup have different boundaries. Raw actions and screenshot counts retain their original units.

Every failed attempt remains separate. Claude’s original GitHub pass followed two failures. Desktop CSV attempt 1 hit a missing paired toolset-name protocol error; one repair attempt produced the correct file but remained 4/5 after a count timeout. Organization setup first failed before generation, then one retry stopped on a drag executor error; there was no third attempt. Recovery’s first correct output earned 4/5 because the local $1 reservation guard stopped final model review. One labeled retry allocated $1.75 from the same cumulative $7 allowance and passed. The initial recovery caps matched across models; the retry’s larger local cap is disclosed rather than treated as matched first-attempt reliability.

Claude’s older CSV recorded 183.18 stopwatch seconds and a 397.54-second UTC span. Saved host power events overlap the stalled request and strongly support sleep as the cause of most of the discrepancy; exact reconciliation is unavailable. Both clocks remain intact and that run is excluded from speed claims. New runs use the stricter wall/monotonic elapsed time and a process-scoped sleep inhibitor.

OpenAI’s CSV and organization runs preceded a click-modifier translation correction: optional SHIFT/CTRL clicks were dropped. The agent completed the required workflows and the artifacts pass, but action counts and timings are confounded. Successful outputs were not rerun. Infrastructure errors are not clean evidence of model inability.

Desktop cumulative estimated usage is $3.6676817 of the original $7 cap, including unsuccessful attempts. The user’s credit top-up did not reset that allowance. Browser and desktop costs stay separate; token estimates, promotional-credit depletion and hosting intervals are not invoices. See [COSTS.md](COSTS.md).

## UI-TARS and publication boundaries

UI-TARS had launch/integrity, token compatibility and permission setup problems. The source patch changed UI-TARS-1.5 Chat Completions output tokens from 65535 to 2048 without changing the endpoint context. Actual browser actions later occurred, but request timeouts prevented a completed GitHub answer and the later suite. Some intended runs stayed unsubmitted. Source-level retry/status analysis is a hypothesis supported by traces, not a tested fix. Browser control alone is not a passed benchmark or a desktop workflow.

This publication assembly made no model request, hosted-fixture deployment, endpoint change or benchmark restart. Private source repositories, original archives and earlier commits are preserved. Public copies omit outside-scope evaluations and private account/control state. Genuine GitHub target URLs, issue titles and observed page text remain task data, not an endorsement or an evaluated configuration. [Provenance](verification/source-provenance.json) identifies the reviewed source archive and copied-byte hashes. Public logs may already have explicit credential/control-URL redaction, provider-ID pseudonyms, omitted image payloads and local-path normalization. Prompt files are retained verbatim where designated; missing evidence is disclosed.
