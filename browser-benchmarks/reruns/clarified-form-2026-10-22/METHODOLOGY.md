# Methodology, changes and limits

## Frozen task and exact shared user prompt

The original form fixture, ten-field reference and exact-text rubric are reused. [Original rubric](../../evidence/additional-tasks/preparation/SCORING.md), [original field specification](../../evidence/additional-tasks/preparation/FORM-RECONSTRUCTION.md), [archived fixture](../../fixtures/index.html). The fixture was not changed, redeployed or replaced. Its original specification was reconstructed before the historical experiment, a previously disclosed limitation. No new values were reconstructed here.

The only intended task change is the user's [exact clarified prompt](clarified-prompt.txt): the Message contains both sentences, and the agent must inspect the entire form/newsletter. SHA-256: `310e61b597776240557a2aed3e5bcbbdaf93a36c26c7c94e52b65d0b576b3007`. Each submitted TinyFish goal and Claude task prompt matches those bytes. The outer user-attachment separators are not sent. TinyFish prepends its usual navigation-to-start-URL sentence in the provider's stored goal; the exact shared user string follows unchanged. Claude retains its original native-tool system instructions. Neither received verifier observations or additional benchmark hints; provider-internal wrappers are not identical contexts.

Three independent runs per agent used a maximum of 600 seconds each. Earlier results were not rerun or overwritten. Planned alternation changed after the pre-agent TinyFish API rejection: actual generation order was Claude 1, 2, 3, then TinyFish 1, 2, 3. This is not randomized or counterbalanced. All six share the same static hosted fixture but browser environments and measurement boundaries differ.

## Existing providers and fresh environments

Claude reused the original unmodified native runner/executor, image claude-benchmark-desktop:v1 (ARM64), Firefox/Linux at 1024×768, alias claude-sonnet-5-5, computer_toolset_20260801, 4,096 output-token cap, 60 native model turns and 300 native-action safety limits. Exact image/browser identifiers and SDK versions are retained in native start events. No model substitution, image rebuild or browser-profile reuse occurred. Each browser-benchmark container began fresh at about:blank, with the original exclusive-use marker, and was removed after its run. Pre-existing unrelated exited containers were preserved. The previously stopped Colima profile was started for these runs and stopped afterward.

TinyFish reused its hosted async integration, lite browser, disabled proxy, no attached profile/vault, and extra read-only captures already used in the prior follow-up. Returned profile_attached=false, and visible initial fields were blank/default. Provider isolation internals, exact hosted browser/OS build and immutable model revision were not exposed. No personal credentials were given to either browser; provider keys were held in a temporary RAM-only broker and used only by the harness. TinyFish is evaluated as a hosted browser agent, not a desktop agent. No attempt was made to infer its opaque internal browser-action mechanism from intent labels alone.

## Budget enforcement and recorded infrastructure problems

The new authorization was **below $2 additional estimated API usage**. TinyFish wallet access showed sufficient existing balance, auto-reload unconfigured, and no pending top-up. Claude model lookup and count-token preflight succeeded without generation; its standard API does not expose account credit balance, so that balance was not independently confirmed. No subscription, top-up or purchase was made.

Initial allocations were $0.33 per Claude and $0.32 per TinyFish, $1.95 total. TinyFish rejected an optional server-side max_steps=20 before creating any run because that field requires beta access. The unsupported field was removed for ordinary supported requests; no beta enrollment, access bypass or created-agent retry occurred. Claude completed all three runs with $0.584368 recorded cost. Released reservations allowed $0.465 per actual TinyFish slot: maximum allocated $1.979368. Models and browser profiles remained unchanged; spending guards differ from the original looser budgets and may censor outcomes.

Normal TinyFish requests retain the default server step budget and the 600-second watchdog. A client spending watchdog watches returned live activity entries, with threshold 19 and ten further steps reserved for reporting/cancellation lag. Polling was shortened from the original four seconds to one second; an additional metadata monitor was used. The provider's aggregate num_of_steps is null while running and is not a usable live counter. A first monitor ownership assertion stopped before monitoring because stored goal includes a provider-added URL prefix; the correction checks the run ID from this batch's submission. This restart affected only metadata monitoring, not an agent. All source/configuration and error notes are retained. The first cancellation observation was 23 live entries; terminal capture contains 24. Eleven cancellation HTTP requests awaited terminal confirmation for that one run. The run stopped at 253.40 client seconds, before 600, for budget protection. Full 600-second completion was not tested for that attempt.

All three Claude model runs finished with zero native tool errors, and then the post-run collector timed out during its viewport-scroll sequence. It had already saved an agent-final image and independent upper image. Existing lower native captures show checkbox/message/status. The original wrapper failure records remain; costs and agent results were recovered from unchanged native summaries/raw usage. No model run was repeated. The later read-only browser-local-storage routine was not reached, so no live DOM checked-property snapshot is claimed.

## Verification and remaining evidence gap

Models made all task interaction decisions. The harness only submitted prompts, executed requested native actions, captured evidence, controlled environment/budgets and independently verified afterward. It did not fill or repair any field, submit, reset a page for an active agent, execute a Playwright task, or send reference data to an agent. Native verifier scrolling was after model stop, at the viewport margin, and is separate from agent actions.

All 76 new images and 47 HTML captures were reviewed. Full success requires ten correct final field states and no submission attempt. Phone punctuation is normalized; other text is exact. Final score never selects an earlier better-looking state. Claude lower images visibly show unchecked newsletters; TinyFish never supplies that view in these runs. HTML contains an unchecked-looking source attribute state but also omits visibly selected radio/text properties. It is not a live-property snapshot and cannot earn a newsletter point. Requested snapshots/elements captures were accepted, but no supported retrievable checked-property artifact or post-terminal live screenshot control was exposed. The failed extra lower capture and unavailable TinyFish lower capture are documented rather than filled in by model assertions.

For TinyFish 2, two observed clear/refill cycles mean final Not submitted alone cannot rule out every possible earlier hidden interaction; no submission action or violating status appears in captured evidence. The reset cause is not established from intent labels. No form interaction by the verification harness occurred while any TinyFish agent was active.

## Timers, units, prices and generalization

Claude's primary timer is the original native runner's agent interval. TinyFish's primary timer starts before async submission and ends at terminal status observation, including queue/transport/status delay; artifact downloads afterward are excluded. TinyFish active intervals were 46, 215 (cancelled), 101 seconds; created-to-start waits were 4, 12, 4 seconds. Client-versus-provider differences are not assigned exclusively to queue time. Provider timestamps have whole-second precision. A cancelled time-to-stop is not a successful completion time. Shorter polling and opaque provider delays limit direct comparisons with the historical runs. Native actions (including screenshots) and provider steps are not normalized into a common action count.

Costs use unchanged recorded model rates ($2/M uncached input, $10/M output; recorded cache categories at their saved rates) and TinyFish's returned $0.016/step tariff. Raw token usage is re-summed offline. TinyFish completed-run debits match tariff counts; cancelled-run billing counter/debit zero conflicts with visible activity, so an uncertainty reservation remains. None is represented as an invoice. Infrastructure, labor and electricity are unpriced. Accounts were not purchased or topped up, and no endpoint/UI-TARS/Sai/OpenAI test was touched.

The changed prompt also adds verification requirements, so this is not an isolated experiment changing only the message boundary. Different dates, nonrandom execution order, model aliases, provider internals, capture gaps and spending censorship prevent a causal or general agent-ranking claim. The earlier ambiguous-prompt cohorts remain separate. Operational reference: [TinyFish API reference](https://docs.tinyfish.ai/agent-api/reference), [run retrieval](https://docs.tinyfish.ai/api-reference/runs/get-run-by-id), [async configuration](https://docs.tinyfish.ai/api-reference/automation/start-automation-asynchronously). These support interface descriptions, not independent proof of task success.
