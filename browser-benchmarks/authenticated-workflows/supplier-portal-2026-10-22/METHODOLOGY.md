# Methodology and limits

**Task and scoring.** Use the [same frozen prompt template](task-template.txt), exact note and a paired equivalent synthetic record for each run. Records SUP-T001…006 and SUP-C001…006 share pair-indexed names and notes. The harness resets only the target to Pending/empty before submission. It never edits or saves the supplier during an evaluated run. No expected confirmation is precomputed or given to an agent. Returned values are parsed only from the original response and compared against stored record state and its save audit after the agent stops. Correct data alone is a partial outcome if the requested final answer is missing.

**Two phases.** Original pilots 1–3 alternated provider order by pair and used the documented spending guards. Two TinyFish pilots were budget-censored. The original all-pilots-success gate prevented the planned extension at that point. A later explicit user amendment authorized exactly three additional attempts each without spending stops. Those use paired records 04–06, TinyFish first (all three), then Claude (all three). This order is not randomized and can confound timing with changing provider conditions. We show each phase separately and retain all-six totals as an attempt history, not an uncensored reliability comparison. No pairs 7–10 were run.

**Authentication.** Each provider is preauthenticated using the same dedicated synthetic account, with distinct session tokens. No credentials in task prompts. TinyFish uses the same dedicated saved Browser Context Profile; Claude uses one persistent Firefox container per phase. Each attempt has a fresh model conversation, not a fresh login. TinyFish receives the dashboard URL as its API start URL; Claude starts at about:blank and must navigate there with the native tool. This starting-view difference and Claude's address-bar work are retained, not normalized away. Session reuse is proved through session hashes in server authenticated-view and save events; public hashes are replaced with consistent aliases. A refreshed session between phases is disclosed. Vault connections were inspected and absent. Server expiry was functionally QA-tested and used for cleanup, but agent recovery after expiration was NOT TESTED.

**Models/tools.** TinyFish normal supported async API, `browser_profile=lite`, saved profile attached, no Vault/proxy, screenshot capture enabled and HTML capture disabled. Its exact model revision/internal browser controller are not exposed. Retained images are 1280×720. Claude `claude-sonnet-5-5`, native `computer_toolset_20260801`, Anthropic SDK 1.15.0, Python 3.12.4, Firefox 153.5.0esr, Linux ARM64 container at 1024×768 on an M1 Mac (8 GB) using the existing Colima VM. Image SHA is in setup identity metadata. Model output cap 4096, original 60-turn/300-action safeguards, SDK retries disabled. Only the native computer tool is provided; no shell, browser automation/DOM or direct HTTP tool performs Claude's task. TinyFish's internal controller is managed and opaque; its prompt prohibits direct API/script task completion, and UI captures/server navigations support observed GUI execution.

**Timers and stops.** Each run has a 600-second execution deadline; no automatic benchmark restart. TinyFish's client timer begins with async submission, includes provider queueing/polling and stops before final artifact download. Claude's native timer includes token counts, generation and action execution; excludes login, about:blank reset, post-run capture and grading. Save full-wrapper timing separately; provider timestamps remain raw. No strict microbenchmark equivalence is claimed. Genuine provider errors, credit exhaustion and deadline stops are recorded. The new batch removes every custom cost-based stop; original cost estimates/reservations remain in historical logs. No automatic top-up or purchase occurred.

**Counts.** TinyFish billable provider steps, trace entries and screenshots are separate metrics; they cannot be equated with Claude's native actions (including screenshot/zoom). Capture counts include one independent post-stop screenshot per Claude attempt, excluded from native action counts; two setup images per phase are separate. TinyFish internal retry counts are unavailable. Repeated Save actions are not benchmark restarts. Claude API retry/error counts and raw generation/token-count request totals are retained. A generic raw Claude `needs_review` placeholder is not its final independent grade.

**Independent verification.** Preserve each post-run owner-API record/audit, original response, raw tool traces, screenshots, pre-run baseline and time/cost metadata. Cross-check complete final records with the native Sites database read tool, separately from the fixture's verifier. Check receipt uniqueness and all other records for unintended saves. Manually inspect all screenshots, then replay grades and token costs offline. Verification data is never sent back to the evaluated agent. Public copies preserve original responses/images byte-for-byte; session aliases, private host paths and control URLs are documented redactions. Secrets, cookies, browser storage, personal profiles, CDP URLs and absolute account balances are excluded.

**Generalization.** One synthetic site, six attempts each with only three uncapped attempts each, unequal model/browser/runtime systems, visible stable layouts and no MFA/captcha/recovery coverage cannot establish production reliability. Different starting states of other displayed records accumulate across runs; each agent is told to change only its assigned Pending target. No data is reset to erase a failure. Scores prove only these records/workflows. Provider invoices, hosting allocations, Mac depreciation/electricity, human labor and prior integration work are not fully measured. Costs are usage estimates/account observations, not total ownership costs.

The Claude returned model string is an API alias, not proof of an immutable underlying checkpoint. TinyFish exposes no immutable model revision or exact browser version here. Profile setup followed the official [Browser Context Profiles API](https://docs.tinyfish.ai/agent-api/browser-context-profiles), [profile concepts](https://docs.tinyfish.ai/key-concepts/browser-context-profiles), [Web Agent reference](https://docs.tinyfish.ai/agent-api/reference) and [Vault setup prerequisites](https://docs.tinyfish.ai/vault-setup). Vault connection count was zero; no password-manager consent was inferred.
