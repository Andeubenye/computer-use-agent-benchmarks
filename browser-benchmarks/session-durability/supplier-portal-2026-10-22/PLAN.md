# Session durability: frozen diagnostic protocol

Three new configurations, one read-only agent run each; no old task reruns. Same portal and task prompt. Maximum agent runtime 600 seconds, no cost threshold, no automatic benchmark restart, no purchases. Vault and expired-login reauthentication NOT TESTED.

1. New dedicated TinyFish Browser Context Profile: log in using supported setup CDP, save, disconnect and let the setup process and its children exit. Stop the setup credential broker. Submit a new Web Agent run from a new controller process with only provider API key, profile ID and verifier credentials; no password/cookies/browser storage. Verify server authenticated-view session hash equals setup session, no new login during task and no supplier writes.
2. Original Claude execution configuration: fresh native Firefox login, stop/remove the original disposable container, create a new container without mounts using unchanged original module. Model alone navigates to dashboard. Evaluate actual restoration, including a correct negative diagnosis if redirected to login. Verify original session remains valid server-side, so client state loss is distinct from expiry.
3. Separate Claude configuration: existing image, new named container and dedicated Docker named volume at Firefox profile path; one bounded ownership initialization. Native login, graceful Firefox shutdown/flush, remove container, new container ID with same volume; model alone checks dashboard. Original source unchanged. Record volume/lifecycle code, process IDs, timings, actions, raw responses, SDK usage and server attribution.

Same prompt requires website interface, no login, no edits, no direct APIs or scripts, and reporting authentication status with visible evidence. Authentication restoration and accurate agent diagnosis are separate measurements. Expire the three newly created synthetic sessions only after verification. Remove owned execution containers/volume, stop VM if originally stopped, and restore the prior synthetic password hash by redeploying the same saved source version. Existing records and evidence remain intact. Session/cookie databases, passwords, keys and control URLs never enter public evidence.
